- **LR1** (docs/bugs/2026-10-19-lab-ios-wda-rn-text-input-wrapped-in-its-component-view-reads-as-a-cover-of-its-own-label.md):
  WDA lists RN's input inside an unnamed `Other` of its own rect, so averi's own-label rule (it asks the input be the
  label's sibling) misses it, and the label — whose centre a raw tap turns into the field's focus — is refused as
  covered. Honest (nothing fired, the reply says so), but a tap a user makes. idb lists the field flat: green.
- **idb typing into an RN field**: two of the four idb fills of a single-line field lost their last character (rn3,
  rn5; rn1's same text whole). The field itself held the short value (averi's read-back `the field shows 8`, the app's
  model 3 s later the same): React Native's controlled input dropping a keystroke of idb's burst, not the oracle
  missing one. averi caught it every time — the LOUD a verifier owes. Not filed as an averi note; under WDA no fill
  lost anything.
- **#18's indicator**: WDA lists M's `Horizontal scroll bar, 1 page` over its label's centre; no reply names it (the
  bar is excused, its parent a text input) — the refusal names the field (LR1). N, a UITextField, lists no indicator.

## The capture fix this run needed

The first Android capture's `rn-field.displays.txt` held the IME (ITYPE_IME visible, `[0,1398][1080,2220]`): the
capture read the IME-down system bands after the probes, and M's probe — a tap on a label that focuses its field —
left the IME up. capture-run.ts now reads them before the probes when the launch shows no IME; no native capture's dump
was affected (none holds a visible IME).
